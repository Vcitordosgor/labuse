G1 — LOT 2 : état du fond coloré par défaut + sélection/clic (vérification)
==========================================================================

RÈGLE DE VIC : en vue île, les parcelles ne sont PAS colorées par défaut. Le fond coloré
par classement ne s'affiche QUE lorsque le client active « Analyse LABUSE ».

VERDICT : conforme APRÈS la réparation de parcels-ile — AUCUN code n'a dû être modifié
          (aucun calque de couleur ne revient par défaut). Mesuré dans l'app (z13, St-Denis) :

  Analyse LABUSE OFF (défaut, l'écran d'accueil) :
    · ile-fill   : visibility=visible, fill-opacity = 0            → AUCUNE couleur de classement
    · ile-line   : visibility=none                                → pas de liseré de tier
    · ile-base   : visibility=none (baseVisible=false)            → pas de voile gris
    → le maillage affiché = contours neutres seulement (capture 01_ile_z13_sans_analyse.png)

  Analyse LABUSE ON (toggle filtres.analyseLabuse + verdict) :
    · ile-fill   : fill-color/fill-opacity = expressions PAR TIER (STATUS_COLOR / opinionOpacity)
    · ile-line   : visibility=visible
    → les parcelles se colorient + le panneau d'analyse s'ouvre
      (415 801 parcelles : 5 952 Excellente · 35 072 Bonne · 49 147 À étudier · 98 386 Faible
       · 227 244 Non retenue) — capture 03_ile_avec_analyse.png

POURQUOI c'est déjà correct : la couleur de classement est pilotée par `opinion`
(MapView.tsx) = (verdict && filters.analyseLabuse) || layers.couleurs_verdict. Par défaut
`opinion` est faux → ile-fill reste à opacité 0. La réparation de parcels-ile réalimente la
source, mais ne force AUCUNE couleur : le gate `opinion` tient.
