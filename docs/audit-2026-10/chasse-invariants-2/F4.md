## Les 5 axes générés

| axe | règles | forme | ce qu'il garantit |
|---|---|---|---|
| **A — bornes du règlement** | 154 | callable (scan YAML) | chaque feuille `valide` numérique ∈ plage plausible (CES [0,100] %, faîtage [0,60] m, égout [0,50] m, recul [0,30] m, pleine terre [0,100] %, places/log [0,10], niveaux [0,20], quota LLS [0,100] %) |
| **B — citation + page** | 46 (23 citation + 23 page) | callable | citation non vide ; `page_pdf ∈ [1, meta.pages_total]` (vraie page du règlement) |
| **C — renvoi** | 15 | callable | chaque zone `renvoi` pointe vers une zone déclarée de la commune |
| **D — propose ne sert pas** | 0 (→ écartée) | SQL | garde moteur déjà pleine : 0 feuille SDP-déterminante `propose` porte une valeur |
| **E — couverture GPU** | 3 | SQL (donnée) | toute parcelle U/AU sous-bâtie à SDP=0 porte une cause ; `regle_plu_non_validee`⟹SDP=0 ; `habitat_interdit`⟹SDP=0 |

### Chaque règle discrimine (test de falsification)
Les callables A/B/C ont été éprouvés sur des valeurs plantées : une feuille à 999 m, une page
p.9999, une citation vide, un renvoi `→Uqqq` déclenchent tous un ECART. Les rubriques E/D
reposent sur des SQL `count(violations)` non vacués : E2 garde 336 parcelles `regle_plu_non_validee`,
E3 garde 5 018 parcelles `habitat_interdit`, E1 garde les U/AU sous-bâties (pct<90) à SDP=0. Le
vert n'est donc pas une absence de matière, c'est une vraie tenue.

## Faux positifs écartés PENDANT la mise au point (traçabilité)

Deux règles candidates ont été **corrigées après un premier run** car elles produisaient des
ECARTs qui n'étaient PAS des défauts (discipline « un faux positif coûte cher ») :

1. **B / page « existe dans l'extrait »** — première version exigeait que `page_pdf` figure dans
   `plu_reglement_extrait`. Or cette table est un **échantillon épars** de pages (p. ex. 97404 :
   12 pages sur 106 ; 97416 : 79 sur 227). 16 communes tombaient en ECART (surtout l'article 6
   stationnement, jamais extrait). **Reformulée** en `page_pdf ∈ [1, meta.pages_total]` — vraie
   borne de document (toutes les pages s'y trouvent déjà : 0 hors borne). L'appartenance à
   l'échantillon épars n'est plus un critère.

2. **E1 / cause écrite** — première version exigeait « toute parcelle U/AU à SDP=0 porte une
   cause ». 63 192 ECARTs. Vérifié : **63 137 d'entre elles ont `pct_potentiel ≥ 90`** — parcelles
   déjà saturées (souvent sur-bâties : `taux_emprise_pct` 141–238 %), SDP=0 légitime et sans
   cause (ce n'est pas un trou). **Resserrée** sur les parcelles *genuinement sous-bâties*
   (`pct_potentiel < 90`) : 0 violation (elles portent toutes une cause). La règle garde son sens
   (un vrai trou muet serait pris) sans la fausse alerte sur les parcelles au plafond.

## ECARTS confirmés

**Aucun.** `OK=218, ECART=0, SKIP=0` sur la base servie q_v18. Toutes les feuilles validées des
23 communes tombent dans les bornes de leur règlement, citent une vraie page, portent une citation,
et aucun renvoi n'est orphelin. Côté données, le gate `propose/valide` du moteur (`zonage._val`)
est étanche : **0 parcelle à SDP servie > 0 ne dérive d'une zone `propose`** (vérifié deux fois —
par le YAML : 0 feuille SDP `propose` porte une valeur ; par la donnée : 336 parcelles
`regle_plu_non_validee` sont toutes à SDP=0).

## Points notables

- **Garde moteur confirmée.** Les 48 feuilles `propose` subsistantes sont toutes **non-SDP**
  (stationnement non chiffrable par logement, ou feuilles SDP sans valeur numérique) : elles ne
  pourraient de toute façon pas brancher une capacité. La réécriture `_val` (validées-only) de
  PLU-CALIBRAGE-6 tient dans la donnée servie.
- **Couverture GPU complète.** Sur les 737 couples (insee, `zone_lib`) portant des parcelles,
  455 matchent directement une zone calibrée/renvoi, 212 sont A/N non-constructibles, et les 70
  U/AU restants (libellés GPU bruts `1AUd`, `UAA`, `UCA`…) résolvent via normalisation/phasage/renvoi
  à une `ZoneRules` définie (calibrée ou générique avec raison). Aucune zone servie n'est un trou
  muet (E1 = 0).
- **CES minimale 0,2 % légitime** (Uep Saint-Pierre = « 20 m²/ha », conversion sourcée Art. Ue3.4
  p.192) : la borne CES part de 0, pas d'un plancher — sinon faux positif sur cette zone
  d'équipement.
- **Saint-André (97409) et Saint-Leu (97413)** ont des calibrages YAML complets mais **0 ligne
  dans `plu_reglement_extrait`** : leurs règles A (bornes) et B (citation + page via pages_total)
  tournent quand même (indépendantes de l'extrait), étiquetées « commune non extraite ».
